# 0.7.0 整体规划：一条命令的 CLI + 会话规模下的性能治理

> 状态：**规划待评审**（设计已出，未开工）。
> 本规划把两件事并成一轮交付：**W1 一条命令跑起来**（npm 全局安装 → harness + console）与 **W2 会话规模下不卡**（checkpoint 拆行 + 详情瘦身）。
> 两份详细设计：W1 → [cli-data-dir-architecture.md](./cli-data-dir-architecture.md)；W2 → [checkpoint-store-split.md](./checkpoint-store-split.md)。

## 1. 交付定义（这轮做完，用户拿到什么）

1. `npm i -g @vuagent/cli` → `vuagent` 一条命令：服务 + console 同端口起来，浏览器直接可用；
2. 状态只落 `~/.vuagent`（可 `paths` 打印、可 `backup`、可 `migrate`），第二次启动被明确拒绝；
3. 长轮次会话不再拖慢系统：单步落盘 **112 ms → < 5 ms**，详情节 **36.7 MB/296 ms → < 1 MB/< 50 ms**，8 会话并发事件循环阻塞 **484 ms → < 50 ms**；
4. 已有数据可无痛迁移（真实库 112 MB 为验收样本）；
5. `0.7.0` 正式版本可发：**Publish workflow** 一条链跑完门禁 → 审核 → 发布 → 冒烟（`NPM_TOKEN` 已配置，alpha/rc 自动进 `next` 通道）；
6. 发布链本身已先行落地（PR0），后续每个里程碑都能用 `dry_run` 复验。

## 4. 架构总览

```
                      npm i -g @vuagent/cli
                               │
                          bin: vuagent
                               │
        ┌──────────────────────┴───────────────────────┐
        │ resolveDataPaths()                            │  ① flag > env > 平台默认
        │   ~/.vuagent/{harness.db,config,logs,exports,run, tmp}
        │ acquireLock(run/harness.lock)                 │  ② 第二实例 exit 3
        │                                               │
        │ createHarnessServer({ dbPath, console:{dir} })│  ③ 显式路径，库默认为 :memory: 不变
        │   ├─ /api/*            → harness 路由         │
        │   ├─ /assets/*         → 静态（immutable）    │
        │   └─ GET *             → index.html（SPA）    │
        │                                               │
        │ serve(127.0.0.1:6880) ──► 打印 data/db/地址    │
        └───────────────────────────────────────────────┘
                               │
        SQLite kv_store ───────┴───────────── 拆行后：
          sessions（元数据）                    session_checkpoints（append-only 快照）
          session_turns（业务数据，< 300 KB）     ↑ O(1) 写入、按需读取
```

## 9. 发布方案（发布链已先行落地）

**三个工作流，各管一件事**：

| 工作流 | 触发 | 职责 |
|---|---|---|
| `ci.yml` | push / PR | 全量门禁（typecheck/test/build/registry+llms 新鲜度/registry 自包含/docs build） |
| `release.yml` | 手动 `action=version` | **只改版本**：changesets 生成/更新 Version Packages PR（不再发包） |
| `publish.yml` | push tag `v*` / 手动（channel + dry_run） | **只发包**：解析版本与 dist-tag → 门禁 → 包内容审查 → `changeset publish --tag` → 发布后冒烟 |

**版本线与 dist-tag**：`0.7.0-alpha.1`(M1) → `alpha.2`(M2) → `beta.1`(M3) → `rc.1`(M4) → `0.7.0`(M5)。含 `-` 的版本自动发 `next`，正式版发 `latest`；`release-plan.mjs` 拒绝「预发布发 latest」，也拒绝「tag 与包版本不一致」（防错发）。

**预发布操作序列**：

```bash
pnpm exec changeset pre enter next   # 进入预发布模式（一次即可，提交）
# → Release(action=version) → Version PR → 合并 → 打 tag v0.7.0-alpha.1 → Publish 自动跑
pnpm exec changeset pre exit         # 出正式版前退出预发布，再走一次 version → tag → publish(latest)
```

**publish.yml 门禁链（顺序失败即停）**：版本一致性（fixed 组，`release-plan.mjs`）→ typecheck/test/build → registry+llms 工件新鲜度 → registry 自包含 → **包内容审查**（`scripts/check-pack.mjs`：禁止 `node_modules`/`.env*`/`src/**`（仅允许 `src/styles/`）、入口与 `bin` shebang 存在性、console 必须含 `dist/index.html`、体积告警）→ `changeset publish --tag <channel>`（provenance + `NPM_TOKEN`）→ push tags → **冒烟**（装发布产物 → `--version`/`paths`/`/api/health`/console 首屏/第二实例退出码 3）。

- 只想校验：`Publish → dry_run=true`（跑全部门禁与审查，不发不推）；`NPM_TOKEN` 已在仓库 secret 配置，`environment: npm` 可按需加人工批准。
- changesets：`@vuagent/cli`、`@vuagent/console` 加入 `fixed` 组（五包同版本），`@vuagent/playground` 继续 `ignore`。
- 回滚预案：npm `deprecate` 该版本 + 文档指向上一稳定版；数据层回滚靠 `inline` 开关 + 迁移前备份；CLI 回滚=装回旧版本（数据目录格式向后兼容）。

# 权限模型与 HITL 审批挂起

> 安全性是企业级 Agent 落地的命门。`@vuagent/server` 采用“同源声明、交集裁决、真·协程挂起”的三重防线，确保敏感操作处于完全受控状态。

---

## 权限模型：交集解析与 Fail-Closed 原则

系统支持三种安全模式：
1. `auto`：全自动模式（仅用于纯只读、无破坏性工具，极少全局开启）；
2. `review`：人机协同审批模式（遇中高风险工具必须人工点击授权）；
3. `read-only`：只读防护模式（拦截一切写工具与命令行工具）。

### 1. 严格交集求值
每次请求的最终生效模式，取 **请求级配置 ∩ 会话级配置**，并且始终由**更严格的一方生效**：
```text
           请求级: auto   ∩   会话级: review   ──▶ 生效: review
           请求级: review ∩   会话级: read-only──▶ 生效: read-only
```
如果请求未声明权限，服务端默认采用 `review` 模式；如果传入了未识别的模式字符串，系统强制降级为 `review`——**安全语义绝对 Fail-Closed，绝不默认放行**。

### 2. Deny-Wins 审批覆盖
在配置工具审批策略时，遵循 **Deny-Wins（拒绝优先）** 准则：
* 配置文件可以为低风险工具追加人工审批；
* 但配置文件**绝不能**私自豁免已被引擎标记为高风险的系统工具（如 `bash`、`fs_write`）。安全项只能升，不能降。

### 3. 同源提示词声明
告诉大模型的规则，与服务端工具守卫执行的规则，出自**同一个纯函数计算**。
这从根本上杜绝了“提示词里说可以做，结果调用被拦截”，或者“提示词说要审批，结果工具直接执行了”的模型-代码认知漂移。

## HITL 审批：真·协程挂起（Promise 语义）

市面上许多实现采用“写入数据库等待位 ➔ 前端定时 1 秒轮询数据库 ➔ 命中后再触发回调”的低效做法，这会导致高延迟和大量无谓的数据库 IO。

Vuagent 采用现代异步的 **协程挂起机制**：

```text
1. 执行段命中高风险工具
   │
   ▼
2. 创建异步挂起 Promise，句柄注册到 SessionPendingActionManager
   │
   ▼
3. 下发 suspended 事件，协程暂停在内存中（完全不占 CPU 计算）
   │
   ▼
4. 用户在前端点击审批，回调 POST /api/action/:id
   │
   ▼
5. 句柄立即 resolve()，挂起协程零延迟被唤醒，继续后续工具调用
```

## 检查点落库与崩溃自愈

如果服务端在协程挂起等待用户审批的这几分钟里，机器遭遇突发重启，会发生什么？

* **挂起即快照**：在协程挂起的瞬间，当前轮次的完整上下文快照、待决工具参数和 `actionId` 会同步落入持久化仓储（SQLite/Redis）；
* **重启恢复**：服务重新启动后，恢复扫描器会把挂起的任务诚实地还原为等待态；用户在前端重新连接后，依然能看到审批卡片并正常点击唤醒，**绝不会把任务吞掉或变成死锁状态**。

## 超时看门狗

每个挂起动作均绑定看门狗定时器：
* 默认超时（如 60 秒）未收到决策，看门狗自动触发 `reject(new TimeoutError())`；
* 协程被自动唤醒并安全终止该操作，向前端广播 `aborted` 事件；
* 彻底杜绝协程在内存中无限期泄漏。

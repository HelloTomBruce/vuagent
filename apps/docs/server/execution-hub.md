# 会话执行枢纽与断线重连

> 这是 `@vuagent/server` 在工程架构上最重要的设计决策：**将 Agent 执行生命周期与 HTTP 连接彻底解耦**。

---

## 为什么绝不能将 Agent 绑定在 HTTP 连接上？

在许多开源或简易的 Agent Demo 中，执行逻辑直接写在 SSE 路由的处理函数内：
```text
[浏览器] ─── 发起 SSE ───▶ [Node.js 路由] ───▶ 启动 ReAct 异步循环
   │                              │                      │
   └── 用户切换标签页 / 断网 ──── 链接断开 ───────────── 循环被抛弃或直接杀死 ❌
```

这种做法在真实生产中会带来灾难性体验：
* 用户切换了会话、刷新了页面、或者移动端息屏 3 秒，正在执行的数据库查询或代码变更任务直接夭折；
* 重新连接后，前面已经生成的思考过程和工具输出全丢了；
* 无法支持多标签页或手机与 PC 同时观察同一个长任务。

---

## 执行枢纽的核心架构

Vuagent 引入了 **会话执行枢纽 (`SessionExecutionHub`)**，将两者彻底拆开：

```text
               ┌────────────────────────────────────────────────────────┐
               │              SessionExecutionHub (后台枢纽)             │
               │                                                        │
               │   AgentLoop (ReAct 循环独立运行，不受客户端连接影响)     │
               │                     │                                  │
               │                     ▼ (写入广播)                        │
               │        环形事件重放缓冲区 (带 seq 序号去重)               │
               │                     │                                  │
               └───────┬─────────────┼─────────────┬────────────────────┘
                       │             │             │
           (订阅连接 A) │ (订阅连接 B) │ (订阅连接 C) │
                       ▼             ▼             ▼
                 [PC 浏览器]    [手机端浏览器]  [管理后台监控]
```

### 1. 后台持续执行 (Detached Execution)
当用户通过 `/api/chat` 发起提问后，Hub 在服务端后台拉起 Agent 协程。即便前端立即关闭网页，**服务端的工具调用、文件读写、模型推理仍然会完整、平稳地执行到终态**并安全落库。

### 2. 环形事件重放缓冲与增量补漏 (Replay Buffer)
Hub 为每个活跃会话维护一个内存环形缓冲区，所有下发的事件均带有从 1 单调递增的广播序号 `seq`：
* **断线重连**：当客户端网络恢复发起重连时，携带最后收到的 `lastSeq`；
* **增量下发**：Hub 仅向客户端重放 `seq > lastSeq` 的事件缺口，既不重复打字，也不漏掉关键卡片；
* **全量快照**：若客户端离线过久超出环形缓冲范围，则通过持久化检查点恢复最新完整视图。

### 3. 多端实时同步订阅 (Multi-client Broadcasting)
同一个会话可以同时被多个客户端（例如多个浏览器标签页、手机 Web 和 PC 端管理后台）建立 SSE 订阅。任何一方触发操作，Hub 会将事件同时广播给所有订阅者，实现毫秒级多端状态同步。

### 4. 并发仲裁与平滑顶替 (Preempt 机制)
如果同一个会话在前一轮任务还在执行时，用户又强行发起了新指令：
* **默认策略**：返回 `409 Conflict`，拒绝冲突；
* **顶替策略（Preempt）**：若请求允许顶替，Hub 会向前一轮任务发送中止信号，但**绝不暴力杀进程**，而是让前一轮任务平稳抽干已产生的数据并安全落库，随后无缝启动新一轮任务，确保数据一致性与数据库完整。
